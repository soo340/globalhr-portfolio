04 ENGINEERING DEEP DIVE

実装でこだわった4つの点。

動くだけでなく、失敗・競合・不正な入力まで考える。

ENGINEERING NOTE 01TRANSACTION

保存失敗を、データ不整合にしない。

社員・在留・更新情報と監査履歴を同じJDBC Connection上で保存。履歴保存に失敗した場合もすべてrollbackします。

IMPLEMENTATION IDEA
connection.setAutoCommit(false);
// employee / visa / renewal / audit
connection.commit();
// failure → connection.rollback();
model/EmployeeDao.java · model/AuditDao.java「保存されたのに履歴がない」を防ぐ設計

※理解しやすいように要約した説明コード。実ファイルの完全な抜粋ではありません。

ENGINEERING NOTE 02CONCURRENCY

古い画面からの上書きを防ぐ。

社員情報と担当・予定情報で別々のrow_versionを管理。更新対象をバージョンで限定し、競合時は409として再読込を促します。

IMPLEMENTATION IDEA
UPDATE GHR_EMP_WORK
SET row_version = row_version + 1
WHERE emp_id = ? AND row_version = ?;
// 0 rows → version conflict
model/EmployeeDao.java · workflow/WorkRepository.javaOptimistic Locking · 409 Conflict

※理解しやすいように要約した説明コード。実ファイルの完全な抜粋ではありません。

ENGINEERING NOTE 03AUTHORIZATION

画面だけでなく、リクエストを守る。

明示したURLだけを許可するdeny-by-defaultのAccessPolicy。毎リクエストでアカウント状態・役割を確認し、CSRFトークンとセッション期限を検証します。

IMPLEMENTATION IDEA
enum Level { PUBLIC, STAFF, ADMIN, DENY }
// deny-by-default route map
// role check + CSRF verification
// session: 30m idle / 8h absolute
auth/AccessPolicy.java · model/AuthFilter.javaRBAC · BCrypt · CSRF · Session

※理解しやすいように要約した説明コード。実ファイルの完全な抜粋ではありません。

ENGINEERING NOTE 04VALIDATION

入力の安全性まで考える。

HTTPフォームだけでなくServiceで必須・日付・長さなどを再検証。CSV数式注入対策、HTMLエスケープ、監査履歴の機密番号マスキングを実装しています。

IMPLEMENTATION IDEA
if (startsWithFormulaCell) value = "'" + value;
// CSV quote escaping
// HTML output: Web.h(value)
// sensitive audit values: [redacted]
util/EmployeeValidator.java · util/Csv.javaServer-side Validation · CSV Hardening

※理解しやすいように要約した説明コード。実ファイルの完全な抜粋ではありません。
