01 / OVERVIEW

プロジェクト概要

社員情報から更新履歴まで、業務データをひとつにつなぐ。

「期限の見落とし」を減らすための管理システム

外国人社員の基本情報と在留資格・有効期限・更新業務を一画面から追跡します。期限の自動分類、更新チェックリスト、操作履歴に加え、データ更新時の競合や不整合まで考慮しました。

ⓘ掲載画面は最終ブランチのJSPをテスト環境でレンダリングしたサンプルです。実運用サーバー・Oracleの稼働画面ではありません。

02 / CAPABILITIES

8つの実装ポイント

画面の見栄えだけでなく、データ処理と業務フローまで。

01
▤

社員マスタのCRUD

社員の登録・編集・削除を共通の検証ルールで処理。社員番号の重複判定、入力エラーのフィールド表示、登録内容の保持に対応。

EmployeeService / EmployeeValidator
02
◷

在留期限・アラート

期限切れ・30日以内・90日以内などを日付に基づいて分類。30/60/90日の絞り込みと、在職者を対象とする期限判定を実装。

期限フィルター / 状態計算
03
☷

更新ワークフロー

在留更新を5段階の進捗として管理し、6項目の書類チェックと担当者メモを保存。更新状態の変更履歴も連動して記録。

5ステップ / 6チェック
04
≡

操作履歴と追跡

誰が・いつ・何を変更したかを記録。社員情報・更新状態の変更を確認でき、機密番号は履歴に複製せず変更有無のみを残す設計。

監査ログ / マスキング
05
⌕

検索・ページング

キーワード、国籍、在留資格、期限状態などで絞り込み。10/20/50件の表示切替とソート、条件付きCSV一括出力をサポート。

10 / 20 / 50件 · CSV
06
▥

集計ダッシュボード

期限状況・国籍別分布・優先対応社員を管理画面に可視化。表示値は実際のレコードからサーバー側で集計。

集計 / 優先対応
07

i18n / 3言語

競合防止 / rollback
03 / ENGINEERING

技術的にこだわった部分

面接で実装の意図を説明できる、3つのテーマ。

ENGINEERING / 01

更新履歴までまとめて確定

社員情報・在留情報・更新進捗と監査履歴を同じJDBC Connectionで保存。途中で監査ログの書き込みに失敗した場合は業務データもrollbackし、部分保存を防ぎます。

EmployeeDao.*WithAudit / AuditDao
COMMIT / ROLLBACK
ENGINEERING / 02

古い画面からの上書きを防止

row_versionを使った楽観的ロックで編集競合を検知。既に更新された社員データを古い画面から保存しようとした場合は409を返し、最新版の再読み込みへ誘導します。

EmployeeService / row_version
OPTIMISTIC LOCKING
ENGINEERING / 03

入力検証を画面とサービスで統一

必須項目・日付・文字数・重複パラメータをサーバー側で検証。直接Serviceを呼ぶ経路でも同じルールを適用し、CSVの出力内容は検索条件に連動させています。

EmployeeValidator / Csv / Web
SERVER-SIDE VALIDATION
更新詳細画面JSP MOCK · DETAIL

5段階の進捗、書類チェック、メモ入力をひとつの画面で管理。

変更履歴画面JSP MOCK · AUDIT
